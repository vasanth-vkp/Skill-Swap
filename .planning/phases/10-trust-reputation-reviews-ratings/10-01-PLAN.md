# Plan 10-01: Backend Review Model, Participant Eligibility, Rating Recalculation Engine & REST Endpoints

## Objective
Implement the server-side review and reputation engine:
- Create `Review` JPA entity and `ReviewRepository` mapped to the `reviews` table.
- Implement `ReviewService` with participant validation, completion state check, duplicate review prevention (max 1 review per participant per exchange), and automated reviewee aggregate rating recomputation.
- Expose REST endpoints via `ReviewController` for submitting reviews, fetching member reviews, and checking exchange review status.
- Write unit tests in `ReviewServiceTest` and integration tests in `ReviewControllerTest`.

## Execution Context
- Spring Boot 3.3.4, Java 21, Spring Data JPA, Spring Security JWT
- Database schema: `reviews` table (defined in `V1__init_schema.sql`), `average_rating` & `total_reviews` columns on `users` table
- Existing files: `User.java`, `ExchangeRequest.java`, `ExchangeStatus.java`

  <action>
    1. Create `ReviewService.java` in `com.skillswap.platform.review.service`:
       - Inject `ReviewRepository`, `ExchangeRequestRepository`, `UserRepository`.
       - `@Transactional public ReviewDto createReview(Long currentUserId, CreateReviewRequest request)`:
         - Fetch exchange: `exchangeRequestRepository.findById(request.exchangeId()).orElseThrow(...)`.
         - Completion check (REV-01): `if (exchange.getStatus() != ExchangeStatus.COMPLETED) throw new IllegalStateException("Reviews can only be submitted for completed exchanges");`.
         - Participant authorization (REV-02): check `currentUserId.equals(exchange.getRequester().getId()) || currentUserId.equals(exchange.getProvider().getId())`. If false, throw `AccessDeniedException("Only exchange participants can submit reviews")`.
         - Single-review check (REV-02): `if (reviewRepository.existsByExchangeIdAndReviewerId(exchange.getId(), currentUserId)) throw new ResponseStatusException(HttpStatus.CONFLICT, "You have already reviewed this exchange");`.
         - Derive counterparties:
           - If `currentUserId.equals(exchange.getRequester().getId())`: `reviewer = exchange.getRequester(); reviewee = exchange.getProvider();`
           - Else: `reviewer = exchange.getProvider(); reviewee = exchange.getRequester();`
         - Save `Review(exchange, reviewer, reviewee, request.rating(), request.comment())`.
         - Aggregate reputation update (REV-03):
           - `Double avg = reviewRepository.calculateAverageRatingForUser(reviewee.getId());`
           - `long total = reviewRepository.countByRevieweeId(reviewee.getId());`
           - Round `avg` to 2 decimals using `BigDecimal.valueOf(avg).setScale(2, RoundingMode.HALF_UP).doubleValue()`.
           - `reviewee.setAverageRating(roundedAvg);`
           - `reviewee.setTotalReviews((int) total);`
           - `userRepository.save(reviewee);`
         - Return `ReviewDto.fromEntity(savedReview)`.
       - `@Transactional(readOnly = true) public List<ReviewDto> getReviewsForMember(Long memberId)`:
         - Query `reviewRepository.findByRevieweeIdOrderByCreatedAtDesc(memberId)`.
         - Map to `ReviewDto`.
       - `@Transactional(readOnly = true) public ReviewStatusDto getReviewStatusForExchange(Long exchangeId, Long currentUserId)`:
         - Query `reviewRepository.findByExchangeIdAndReviewerId(exchangeId, currentUserId)`.
         - Return `new ReviewStatusDto(opt.isPresent(), opt.map(ReviewDto::fromEntity).orElse(null))`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> ReviewController | Authenticated member submits 1-5 star review for completed exchange |
| Public -> ReviewController /member/{id} | Public member profile queries reviews received |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-01 | Tampering | ReviewService | high | mitigate | Submissions rejected if exchange status is not COMPLETED; third parties receive 403 |
| T-10-02 | Denial of Service | ReviewRepository | high | mitigate | Max 1 review per participant per exchange enforced by service check and unique DB constraint |
| T-10-03 | Information Disclosure | ReviewController | low | mitigate | Review DTOs expose only public fields (name, avatar, rating, comment, date); sensitive data excluded |
| T-10-04 | Tampering | ReviewService | high | mitigate | Average ratings and total review counts computed strictly server-side inside @Transactional |
