# Plan 09-01: Backend Transactional Settlement Service, Credit Ledger, Idempotency Guards & REST Endpoints

## Objective
Implement the server-side transactional time-credit settlement engine and immutable audit ledger:
- Create `CreditTransaction` JPA entity and repository mapped to the existing `credit_transactions` database table.
- Build `WalletService` with atomic settlement logic (`settleExchange`), idempotency checks, negative balance guards, wallet summary metrics, and transaction history.
- Integrate settlement into `ExchangeService.confirmCompletion` upon dual confirmation, and record `INITIAL_GRANT` transactions in `AuthService.register`.
- Expose REST endpoints via `WalletController` (`GET /api/v1/wallet/me` and `GET /api/v1/wallet/transactions`).
- Write comprehensive unit and integration tests verifying transfer mechanics, idempotency, and security constraints.

## Execution Context
- Spring Boot 3.3.4, Java 21, Spring Data JPA, Spring Security JWT
- Database schema: `wallets` and `credit_transactions` tables (defined in `V1__init_schema.sql`)
- Existing files: `ExchangeService.java`, `AuthService.java`, `Wallet.java`, `WalletRepository.java`

    1. Create `WalletService.java` in `com.skillswap.platform.wallet.service`:
       - Inject `WalletRepository`, `CreditTransactionRepository`, `UserRepository`.
       - `@Transactional public void settleExchange(ExchangeRequest exchange)`:
         - Idempotency guard: `if (creditTransactionRepository.existsByExchangeId(exchange.getId())) return;`
         - Check duration: `BigDecimal amount = exchange.getDuration() != null ? exchange.getDuration() : new BigDecimal("1.00");`
         - Retrieve requester wallet: `Wallet requesterWallet = walletRepository.findByUserId(exchange.getRequester().getId()).orElseThrow(...)`
         - Solvency guard: `if (requesterWallet.getBalance().compareTo(amount) < 0) throw new IllegalStateException("Insufficient credit balance to settle exchange");`
         - Retrieve provider wallet: `Wallet providerWallet = walletRepository.findByUserId(exchange.getProvider().getId()).orElseThrow(...)`
         - Deduct from requester: `requesterWallet.setBalance(requesterWallet.getBalance().subtract(amount));`
         - Add to provider: `providerWallet.setBalance(providerWallet.getBalance().add(amount));`
         - Save wallets: `walletRepository.save(requesterWallet); walletRepository.save(providerWallet);`
         - Record transaction: `CreditTransaction tx = new CreditTransaction(exchange, exchange.getRequester(), exchange.getProvider(), amount, "EXCHANGE_TRANSFER");`
         - Save transaction: `creditTransactionRepository.save(tx);`
       - `@Transactional public void recordInitialGrant(User user, BigDecimal amount)`:
         - Create and save `CreditTransaction` with `sender = null`, `receiver = user`, `amount = amount`, `type = "INITIAL_GRANT"`.
       - `@Transactional(readOnly = true) public WalletSummaryDto getWalletSummary(Long userId)`:
         - Retrieve balance from `walletRepository.findByUserId(userId)` (defaults to 0.00 if absent).
         - Query `calculateTotalEarned(userId)`, `calculateTotalSpent(userId)`, `countCompletedExchanges(userId)`.
         - Return `WalletSummaryDto`.
       - `@Transactional(readOnly = true) public List<CreditTransactionDto> getTransactionHistory(Long userId)`:
         - Query `creditTransactionRepository.findByUserIdOrderByCreatedAtDesc(userId)`.
         - Map to `CreditTransactionDto` using `CreditTransactionDto.fromEntity(tx, userId)`.
    2. Update `ExchangeService.java`:

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Tampering | WalletService | high | mitigate | Balances modified only via server-side `@Transactional` methods; client cannot edit |
| T-09-02 | Repudiation | CreditTransactionRepository | high | mitigate | Every credit transfer records immutable `CreditTransaction` row with timestamps and parties |
| T-09-03 | Information Disclosure | WalletController | med | mitigate | User principal injected via JWT security context; cannot view another member's wallet |
| T-09-04 | Tampering | WalletService | high | mitigate | Idempotency guard prevents duplicate settlement if completion is processed more than once |
| T-09-05 | Tampering | WalletRepository | high | mitigate | Solvency check prevents negative balance; backed by database `chk_wallet_balance_positive` |
</threat_model>
